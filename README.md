# 美股研究编排 Skill

`stock-research` 将一组美股研究 prompt 组织为可追溯的研究流程，支持个股完整研究、专项更新和 AI 周度复盘。

它由 Codex等工具读取并执行：按需加载研究模块、获取资料、检查证据、形成多空论证，最后生成报告。它不是独立运行的 Python 程序，也不提供行情数据库、自动交易或定时调度服务。

> 当前交付目录仅包含本 README，未包含可安装的 Skill 源码。下文对应此前实现的 `stock-research`；安装前需准备完整目录，至少包含 `SKILL.md` 及其引用的 `references/`、`assets/`。仅复制 README 不会安装 Skill。

## 运行模式

| 模式 | 适用场景 | 执行范围 |
| --- | --- | --- |
| 完整研究 `full` | 按整套 prompt 研究一只股票 | 六路研究、证据检查、多空论证和综合裁决 |
| 专项更新 `update` | 更新新闻、财报、技术等内容 | 更新相关模块，必要时重新评估投资逻辑 |
| 周度复盘 `weekly` | 回顾美股交易周、AI 周期与观察清单 | 市场与 AI 证据、重要标的复核、下周情景与观察条件 |

完整研究的主要顺序：

```text
统一输入与时间边界
        ↓
公共事实底稿与来源清单
        ↓
市场 / 行业 / 基本面 / 技术 / 新闻 / 社媒
        ↓
来源、口径与事实冲突检查
        ↓
看涨论证 + 看跌论证
        ↓
综合裁决与报告校验
```

默认由一个 agent 分阶段执行。单 agent 的多空分析共享对话上下文，不等同于两位完全独立的分析师。只有明确允许委派且宿主提供相应工具时，才采用多个 agent 执行独立任务。

## 安装到 Codex

### 推荐：直接放入项目扫描目录

将完整的 `stock-research` 文件夹放到项目的 `.agents/skills/` 下：

```text
项目目录/
└── .agents/
    └── skills/
        └── stock-research/
            ├── SKILL.md
            ├── agents/
            │   └── openai.yaml
            ├── references/
            └── assets/
```

注意目录名是 **`.agents`**，不是 `.agent`。不要多套一层同名目录；最终应能直接找到 `.agents/skills/stock-research/SKILL.md`。

在 Codex 中打开该项目。Codex 会扫描约定位置中的 Skill，先读取名称和描述，在需要使用时加载完整指令。若新增 Skill 没有出现，可重启 Codex 后检查。

只将文件夹放在普通的 `skills/` 目录中，并不能保证 Codex 自动发现它。

### 可选：保留源码目录，添加软链接

也可以把实际文件放在项目的普通 `skills/` 目录，再建立入口：

```text
项目目录/
├── skills/
│   └── stock-research/          # 实际文件
└── .agents/
    └── skills/
        └── stock-research      # 软链接 → ../../skills/stock-research
```

Codex 支持软链接。两处指向同一份内容，不需要维护两份副本；但移动或删除源目录会导致入口失效。对于只在一个项目中使用的情况，直接存放通常更简单。

不要同时在多个扫描位置安装同名副本，以免出现重复入口或版本不一致。需要跨项目使用时，可将完整 Skill 放入个人目录 `~/.agents/skills/stock-research/`，并清理不再需要的项目入口；操作前确认不会删除其他版本或文件。

官方规则见：[Codex Skill 文档](https://learn.chatgpt.com/docs/build-skills)。

## 快速开始

安装后，在 Codex 对话输入框发送以下指令。它们是对话指令，不是终端命令。无需手动逐个粘贴研究员 prompt。

### 完整研究一只股票

```text
使用 $stock-research 完整研究 NVDA。
投资周期为未来 6–12 个月，技术面单列未来 10 个交易日。
使用截至当前可获得的数据，中文输出，并注明来源和数据限制。
```

将 `NVDA` 替换为目标股票。未给出股票时，Skill 应先询问，不把示例股票当成默认研究对象。

### 更新新闻或基本面

```text
使用 $stock-research，只更新 NVDA 最近一周的新闻和基本面。
判断新增信息支持或削弱了哪些投资假设。
```

要与前次研究比较，请附上上次报告，或提供可读取的运行目录路径。没有前次底稿时仍可做专项分析，但不能声称“较上次改善”或“原逻辑已被推翻”。

### 做 AI 周度复盘

```text
使用 $stock-research 做最近一个完整美股交易周的 AI 周度复盘。
关注 QQQ、SMH、NVDA。
我未提供持仓，只分析观察清单，不推断个人仓位。
```

默认使用最近一个完整交易周。若希望覆盖尚未结束的本周，请明确写“本周至今”；报告会注明这是部分交易周。

### 仅依据提供的资料

```text
使用 $stock-research 分析我附上的公司财报和新闻资料。
只依据这些资料，不联网；缺少行情或其他证据时明确说明。
```

离线资料不能支撑实时行情判断。缺少原始行情序列时，不会凭空补齐均线、支撑位或最新价格。

## 可以指定的输入

无需先填写配置文件，在自然语言中说明即可：

| 输入 | 说明 |
| --- | --- |
| 标的 | 股票代码、公司名称；有证券身份歧义时先核验 |
| 模式 | 完整研究、专项更新或周度复盘 |
| 信息截止时间 | 未指定时使用运行开始时的实际时间；可指定历史时点 |
| 投资周期 | 完整研究默认 6–12 个月，并另看未来三年增长假设 |
| 技术窗口 | 默认未来 10 个交易日，与长期估值期限分开 |
| 新闻窗口 | 默认最近 7 个自然日；周报和更新按对应时间边界处理 |
| 上次报告 | 用于追踪变化；不会自动假定已有基线 |
| 观察清单 | 周报优先使用用户提供的范围，不默认逐只做完整研究 |
| 持仓与约束 | 可选；缺失时不推断成本、权重或风险承受力 |
| 输出格式 | 默认中文 Markdown，也可明确提出其他格式要求 |

研究历史时点时，只能采用当时已经公开的信息。无法取得历史版本或确认发布时间的资料，应在报告中注明限制。

## 研究模块

| 模块 | 主要问题 |
| --- | --- |
| 市场 | 宏观、流动性、市场广度、估值与近期风险 |
| 行业 | 周期、竞争结构、增长驱动、单位经济与行业 KPI |
| 基本面 | 商业模式、护城河、管理层、盈利质量、订单和增长假设 |
| 技术 | 日周趋势、均线、关键价位与失效条件 |
| 新闻 | 事件核验、财务传导、预期差与投资逻辑变化 |
| 社媒 | 有明确样本范围的热度、情绪和叙事观察 |
| 看涨 | 同一事实底稿下的最强多头论点、催化剂与反证 |
| 看跌 | 同一事实底稿下的核心风险、脆弱点与验证条件 |
| 综合 | 处理分歧，整合情景、估值及条件式研究意见 |

各模块交付结论、证据、反证、时间窗口、失效条件和数据缺口。多空双方共享同一版事实底稿，不得各自补造数据。

## 输出在哪里

默认保存在执行任务时的当前项目目录下：

```text
research-output/
└── 运行时间-模式-标的/
    ├── request.json       # 本次输入、默认假设与信息截止时间
    ├── progress.json      # 执行状态、依赖与输出位置
    ├── sources.md         # 来源、日期、口径与数据缺口
    ├── checks.md          # 来源、冲突、覆盖及算术检查
    ├── modules/           # 各研究模块底稿
    └── report.md          # 最终报告
```

运行结束时，Codex 应给出最终报告链接，并说明未覆盖内容。每次新研究使用独立目录，不覆盖前次结果。

模块可能是 `complete`（完成）、`degraded`（部分资料不足）、`blocked`（关键证据不足）或 `skipped`（未选择）。这些状态反映研究覆盖，不表示股票看多、看空或风险为零。

中断后，可提供本次运行目录并要求继续；Skill 应核对输入和截止时间，从未完成步骤恢复。刷新数据或改变研究范围时，应建立新运行。

## 数据要求与边界

- 动态事实需要本次可核验的来源。安装 Skill 不会自动取得券商、金融数据库或社交平台权限。
- 拿不到某项数据时，明确说明缺项和影响。少量社媒帖子不代表全平台情绪，社媒热度也不能证明机构资金流向。
- 区分事实、推论、估算与主观情景。目标价需要估值依据，技术支撑不能替代内在价值。
- 情景概率是主观假设，不是统计胜率；没有充分依据时不强制输出概率或期望收益。
- 缺少个人组合和风险约束时，不给个性化仓位、具体期权合约或卖空数量。
- 只提供研究，不自动下单、修改账户、对外发布或创建定时任务。
- “每周复盘”是一种运行模式，不代表已设置每周自动执行。

真实研究效果需要用具体标的和可用资料试跑后检查。文件格式或链接校验通过，不代表数据已经验证、结论可靠或策略经过回测。

## 与 Public Equity Investing 的关系

本 Skill 负责这组 prompt 的执行顺序、公共事实底稿、模块交接和报告整合。普通公司研究、单项估值或财报分析优先使用现有 Public Equity Investing。

在该插件可用时，按需复用其公司事实、财报、估值、多空研究或报告校验能力；不可用时，采用本 Skill 内置模块并说明限制。插件和数据源的可用性以本次实际检查为准。

## 修改与维护

完整源码目录中，各部分职责如下：

| 文件或目录 | 修改内容 |
| --- | --- |
| `SKILL.md` | 触发条件、总控流程、共同规则和完成门槛 |
| `references/contracts.md` | 输入、来源、模块交付及运行状态约定 |
| `references/modes.md` | 三种模式的依赖与更新传播规则 |
| `references/integration.md` | 与已有研究能力的衔接方式 |
| 其他 `references/*.md` | 各研究员的方法与周度复盘规则 |
| `assets/research-report.md` | 个股报告模板 |
| `assets/weekly-report.md` | 周报模板 |
| `agents/openai.yaml` | 显示名称、简介及默认调用示例 |

修改后检查相对引用是否有效、输入输出是否一致、数据不足时是否能正确降级。不要将特定股票代码写死到通用模块里，也不要只修改名称却遗漏目录或调用示例。

## 常见问题

**放一个 README，Codex 就会识别吗？**  
不会。需要完整且格式正确的 `SKILL.md`，放在 Codex 的扫描位置，并确保其引用资源可读取。

**需要在终端执行 `$stock-research` 吗？**  
不需要。它是在 Codex 对话中明确指定 Skill 的写法，不是 shell 命令。

**为什么普通 `skills/` 里有文件，却找不到 Skill？**  
普通文件夹不是约定的项目入口。将完整目录放到 `.agents/skills/` 下，或在该位置建立有效软链接。

**为什么以前能识别，移动目录后不行了？**  
检查入口是否为软链接、链接目标是否仍存在，以及 Codex 当前打开的项目是否正确。源目录移动后，需要更新链接。

**拿不到社媒数据会让整个研究失败吗？**  
不会自动导致整个流程失败。相关模块应标注缺口，其他有证据支持的研究可以继续；最终报告必须保留覆盖限制。

**怎样确认这次确实执行了整套流程？**  
检查最终报告、`progress.json`、模块底稿和来源记录是否一致。不能仅凭一份长报告就认为六路研究和多空论证全部完成。
